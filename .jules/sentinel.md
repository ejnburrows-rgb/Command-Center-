## 2025-02-15 - Fixed Timing Attack Vulnerability in Authentication
**Vulnerability:** The API route for authentication (`app/api/auth/route.ts`) compared the user-provided passphrase to the expected `PORTAL_PASSPHRASE` using a standard string inequality operator (`!==`).
**Learning:** Standard string equality operators compare strings character by character, returning `false` early upon encountering the first mismatch. This timing difference allows attackers to gradually guess the expected passphrase by observing the time taken to respond to different inputs. The time increases as more characters of the guessed passphrase match the expected passphrase.
**Prevention:** Always use constant-time comparison functions, like `crypto.timingSafeEqual`, when verifying passwords, passphrases, secrets, or HMACs. Since `timingSafeEqual` requires the input buffers to be of equal length, hash the user input and the expected secret using `sha256` before comparing them. Additionally, validate the input type (e.g., `typeof body.passphrase === 'string'`) before passing it to `crypto.createHash().update()` to avoid `TypeError` unhandled exceptions that could crash the service.
