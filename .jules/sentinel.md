## 2024-11-11 - Timing attack vulnerabilities in passphrase checking
**Vulnerability:** Found direct string comparison operators (`!==`) being used to compare user-provided passphrases and session tokens with sensitive secret values in `app/api/auth/route.ts` and `app/api/artwork-intake/route.ts`.
**Learning:** These comparisons were susceptible to timing attacks, as direct string equality checks can exit early on the first mismatched character, allowing an attacker to deduce the secret byte by byte by measuring response times. Next.js API routes compiled for Edge runtime might not support `crypto` natively without correct configuration, but the routes correctly explicitly specified Node.js runtime.
**Prevention:** Always use `crypto.timingSafeEqual` with `Buffer.from()` to compare secrets or hashes, ensuring comparisons are executed in constant time. When comparing inputs of potentially variable length (like passphrases), hash them first to fixed lengths (e.g. SHA-256) or explicitly check lengths before running `timingSafeEqual`, to prevent length mismatch exceptions.
